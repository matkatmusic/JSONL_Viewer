### 1b. Implementation: `jfred/src/layered_git_beacons.ts` (new)

One exported function reusing the `reconstruction_git_evidence.ts` execSync
patterns (try/catch → absence is a silent skip) and
`widenCommitterSecondsToInstant` from `src/layered_instants.ts`:

```ts
export function collectCommitBeaconNodes(repoPath: Path, filePath: Path): BeaconNode[]
```

- `relative(repoPath, filePath)`; `""` or `..`-prefixed → `[]` (same guard as
  `readCommittedFileContent`).
- `execSync(`git log --format="%H %ct" -- ${JSON.stringify(rel)}`, { cwd, stdio: "pipe" })`
  — `%ct` is committer epoch seconds; author time (`%at`) is never read.
  Failure (no repo) → `[]`.
- Parse lines to `{ hash, committerEpochSeconds }`; REVERSE so the oldest
  commit comes first (timeline order).
- For each: `git show hash:rel` (private helper, try/catch → skip the commit
  — a commit that deleted the file has no blob) → node
  `{ kind: LayeredNodeKind.beacon, instant: widenCommitterSecondsToInstant(seconds), content, evidence: undefined }`.
- Keep small private verb-named helpers (`listCommitsTouchingFile`,
  `readBlobAtCommit`); module stays well under the 250-line cap.
- Do NOT wire into `loadLayeredProject` — merging git beacons onto session
  timelines is S5/task 202's job. Say so in the module header comment.

### 2b. Implementation: `jfred/src/layered_snapshot_beacons.ts` (new)

`src/reconstruction_backup_timeline.ts` and the `BackupReader` type from
`src/reconstruction_sidecar.ts`:

```ts
export function collectSnapshotBeaconNodes(
    records: TranscriptRecord[],
    reader: BackupReader,
```
