## Context the Next Agent Won't Have

**The `files` array in tasks.json is load-bearing and cost this session four
failed runs.** Workers are told "touch nothing outside them" and correctly refuse
when the plan needs a file the grant omits. Three separate rounds produced ZERO
work because the grant was too narrow or named the wrong folder. Always derive
`files` from the plan file on disk, never from the brief and never by guessing.

**Re-running a workflow re-runs the planner, which OVERWRITES the plan file.**
Task 347's plan was rewritten between runs with the opposite folder name and
structure, invalidating a `files` array built from the previous version. Use
`resumeFromRunId` so planners replay from cache and cannot rewrite plans.

**`merged: true` does not mean work happened.** A blocked worker makes no commits,
so its branch merges cleanly and empty. Always verify with
`git diff --stat <base> <branch>` before believing a merge result.

**Git requires a clean INDEX to merge**, even when the incoming files do not
overlap the staged ones. `git merge-tree` will NOT tell you this — it only checks
tree content. The working recipe: `git restore --staged <paths>`, merge, re-stage.

**DOM tests pass while the UI is visibly broken.** Task 334's minimap marks were
built and inserted correctly but had no CSS rule at all, so they were invisible.
The agent that "fixed" 334 never touched the minimap and its DOM assertions all
passed. Honour the CLAUDE.md rule: visual fixes need a real browser.

**Check `scenarios/` before claiming the engine lacks something.** The user
corrected this session sharply. A scenario existing means the engine already
handles that case. The DSL marks rewind kind directly: `Rewind: N` is
conversation-only, `Rewind: N, code` is a code rewind, and they exist as twin
pairs s12/s11, s14/s13, s17/s16, s19/s20, s22/s23, s59/s60. Recon docs under
`plans/340-recon/` describe what was unknown *during recon* and go stale — they
are not a statement of engine capability.

**RevEng worktrees spawn with an empty `jfred` submodule and no `node_modules`.**
Run `git submodule update --init jfred` and symlink `node_modules` from the main
checkout, or typecheck fails with `TS2688: Cannot find type definition file for
'node'` and reports a false pass/fail.

**`NODE_OPTIONS` contains a VS Code JS-debug bootloader that hangs `tsc` and
`node --test`.** Prefix every invocation with `NODE_OPTIONS= `.

**User preferences expressed this session:** merges are always `--no-ff`; "merge"
never implies push; nothing gets committed without being asked; regressions in
