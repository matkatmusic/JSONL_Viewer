## Context the Next Agent Won't Have

**RevEng worktrees get their OWN submodule object store, and merging does not
move objects. This destroyed four tasks' work.** `git submodule update --init
jfred` inside a worktree clones into
`.git/worktrees/<name>/modules/jfred` — a separate object database. Workers
committed their jfred changes there. `mergeTaskWorktrees.ts` merged the RevEng
superproject (which carries only a gitlink) and then deleted the worktrees,
taking the objects with them. Commits `222fc0d` and `a549a0f` were confirmed gone
from all 3750 git dirs under `/tmp`. **Before any future worktree run touching a
submodule: work in the main checkout, or fetch each worktree's submodule commits
into the parent BEFORE the merge script removes it.**

**`merged: true` from the workflow means nothing.** Groups 1, 2, 3 and 5 all
reported `merged: true` and produced ZERO commits — an empty branch merges
cleanly. Only group 4 produced a merge commit, and it pointed at a dead object.
Always check `git log` / `git diff --stat`, never the workflow's own report.

**A PostToolUse comment-reflow hook rewrites files between edits and records no
tool call.** It joins consecutive `//` comment lines into one line separated by
TWO spaces. This is why replaying recorded edits onto a clean git base diverges:
the agent's next `old_string` reflects post-hook content that no recorded
operation produced. The replay tool works around it by seeding from the newest
full `Read` result instead of from git. It will also reflow the next agent's own
comments mid-edit — expect the hook to block on comments over 20 words.

**Workflow-subagent transcripts barely populate `toolUseResult`** — 0 of 27 user
records in one case. The engine's file-event extraction is driven entirely by
that field, so `Edit` operations vanish silently: `editEventFrom`
(`reconstruction_extract.ts:40`) returns `undefined` when `detailById` has no
entry, and the caller pushes nothing. `Write` is unaffected — it builds from
`tool_use.input` directly (line 67). That asymmetry is the whole bug.

**`Read` tool results render a phantom trailing empty numbered line** (e.g. a
91-line file shows `91\t` after the last real line). Parsing Read output without
dropping it adds a spurious `+1` to every reconstructed file.

**Failed tool calls are still recorded as `tool_use` blocks.** Two Edits in this
batch errored. Replaying them corrupts the result. Always check the paired
`tool_result` for `is_error: true`.

**The jfred test suite is environment-sensitive and will lie to you.** A scratch
checkout produced 9 phantom failures until three conditions were met: the
directory must be **named `jfred`** (a test asserts the URL ends with "jfred"),
the `scenarios` submodule must be present (symlinking the real one works), and a
sibling `plans/` directory must exist alongside the checkout. Get a green
baseline on unmodified code before trusting any failure.

**`tackle-tasks` tells workers to run typecheck ONLY, no test suites.** Full
verification is deferred to `close-tasks`, which never runs if the merge fails.
Tasks 365 and 367/368 shipped with 5 failing tests nobody saw. **Do not treat a
worker's "typecheck clean" as evidence the work is correct.**

**The recorded diffstats are a real oracle.** Every commit's
`N files changed, +X -Y` line is in the transcripts, which is how the recovery
was proven exact rather than plausible. Use them any time work is reconstructed.

**User preferences reaffirmed this session:** merges are always `--no-ff`;
"merge" never implies push; nothing is committed without being asked; visual
verification is the user's job, not a CDP script's; when work is recovered,
commit it faithfully first and fix defects in SEPARATE follow-up commits so the
diffstat oracle still proves the recovery.

**The permission classifier blocked several operations this session** —
`git worktree remove`, `git branch -D`, and the `create-task` skill's task-number
script. Hand those to the user rather than working around them.

**`NODE_OPTIONS` contains a VS Code JS-debug bootloader that hangs `tsc` and
`node --test`.** Prefix every invocation with `NODE_OPTIONS= `.

**`close-tasks` and `tackle-tasks` arguments reach the shell inside single
quotes** — apostrophes, parentheses and backticks in the reasoning text break the
invocation.
