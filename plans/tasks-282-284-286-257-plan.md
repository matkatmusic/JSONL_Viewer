  that in a comment: the task's created-at caveat is about a node this layer does not yet draw,
  so there is nothing to gate here yet.

On click:
1. Resolve the owning `.filebox` and its `.fname` `data-path`.
2. Commit node → the hash is on the `.node`'s `title` (`buildPairWidget` sets it, full 40 chars).
   Fetch `/api/layer1-file?repo=<#repo>&path=<path>&hash=<hash>`.
   Disk node → fetch `/api/layer1-file?dir=<#dir>&path=<path>`.
3. Header (`#dpath`): `` `${basename} — at commit ${hash.slice(0, 8)}` `` or
   `` `${basename} — Current on-disk state` ``; `title` = the full path.
   `#dmeta`: `` `${path}   ·   git show ${hash}:${path}` `` or `` `${path}   ·   working tree` ``.
4. `renderFileContentInto(getRequiredElementById("dbody"), content)`; a failed fetch puts the
   response text there instead.
5. `highlightLandedElement(node)` — clicking a node to inspect it IS selecting it, in the same
   highlight language a ruler-tick landing speaks.
6. `#drawer.classList.add("open")`, then in a `requestAnimationFrame`:
   `node.scrollIntoView({ block: "nearest", inline: "center" })` and `drawLayer1Minimap()`. The
   drawer SHRINKS the pane, so re-centring must be measured against the POST-reflow layout —
   which is also why `.drawer` must carry no width transition.
7. `#dclose` closes the drawer and re-runs `drawLayer1Minimap()`.
